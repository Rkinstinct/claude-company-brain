Company Brain עם Claude

בונים מאגר ידע ארגוני קטן, בלי לתת ל-Claude גישה לכל הארגון.

מהו Company Brain בפועל

לא "מוח" אחד שיודע הכל, אלא שירות חיפוש ותשובות שמחזיר מידע מאושר עם מקור, תאריך והרשאות. מתחילים בתחום מצומצם, למשל נהלי BI שפורסמו לכל הצוות. Claude יכול לעזור לכתוב את צינור העבודה ולנסח תשובות, אבל אינו שואב את כל המידע מהארגון בעצמו. כל מקור דורש בעלים, דרך קריאה מורשית, מפת הרשאות, החלטת שמירה ורענון.

האתר הזה ציבורי ומכיל הדרכה בלבד. אל תעלו אליו מסמכי חברה, URLs פנימיים, רשימות עובדים, מפתחות, דוגמאות מתוך דוחות פרטיים או פלט משיחות פנימיות. צוות אבטחה חייב לאשר כל חיבור אמיתי. התחילו רק בנתונים דמיוניים או ציבוריים.

מאיפה בדיוק שואבים את הדאטה?

מקור דרך טכנית התחלתית מה לבקש מהבעלים בעיית הרשאות
נהלים ו-FAQ מאושרים ייצוא .txt/.md לתיקייה מקומית או API של מאגר מסמכים מי מאשר גרסה ומה תאריך הרענון המשתמשים לא בהכרח רשאים לראות כל מסמך
SharePoint / OneDrive / Drive API רשמי בחשבון שירות מוגבל, או ייצוא ייעודי מאושר הרשאות קריאה לתיקייה ספציפית בלבד לשמר ACL לכל קובץ, לא רק הרשאת הסורק
כרטיסי Jira / Linear / מערכת קריאות API רשמי עם סינון פרויקט, סטטוס ותגי סודיות איזה פרויקט ושדות מותרים הערות וקבצים מצורפים עלולים להיות מוגבלים
SQL / Power BI semantic model שאילתות מאושרות, read-only, על טבלאות/מדדים נבחרים מילון מדדים, בעלות ו-RLS לא לעקוף RLS באמצעות חשבון שירות רחב
Slack / Teams / מייל רק אם יש צורך מוכח, הסכמה וגבולות שימור ערוצים ותאריכים מדויקים הודעות אישיות, PII ומידע צד שלישי דורשים בדיקה נפרדת

המסלול הראשון למתחילים אינו connector למערכות חיות: בעל המידע מייצא 5 מסמכים מותרים ל-data/approved/, עם source_id, בעלים, תאריך ועדכון. Claude Code קורא רק תיקייה שהרשיתם לו. לחיבור ישיר של Claude Code למערכות משתמשים ב-MCP או בכלים מותאמים, אך connector מקבל את הרשאות המשתמש/הטוקן שלו; עצם החיבור אינו מאשר העברת תוכן לספק או פרסום. בדקו כל connector ואת הרשאות Claude Code לפני שימוש.

שלב 1: בוחרים מקרה שימוש קטן

הגדירו 10 שאלות אמיתיות שהצוות שואל על נוהל ציבורי בצוות, למשל "מי מאשר שינוי במודל?" ו-"מתי מעדכנים gateway?". רשמו לצד כל תשובה קובץ ומקום בטקסט. הוסיפו חמש שאלות שהתשובה אליהן אינה במסמכים. זה הסט שאיתו תבדקו את המערכת, לפני שמחברים דאטה.

שלב 2: אוספים ומסדרים קבצים מורשים

צרו מבנה מקומי. קובצי הדוגמה ב-data/approved הם פיקטיביים:

company-brain/
  data/approved/bi-policy.txt
  data/approved/gateway-faq.txt
  manifest.csv
  app.py

manifest.csv הוא רישום שהשרת יוצר מתוך מידע אמיתי שאומת מול בעל המקור, לא הוראות קסם ל-Claude:

source_id,path,owner,classification,updated_at,allowed_group
bi-policy,data/approved/bi-policy.txt,BI-team,internal-demo,2026-09-27,bi-readers
gateway-faq,data/approved/gateway-faq.txt,BI-team,internal-demo,2026-09-27,bi-readers

אל תעלו את data/, manifest.csv הארגוני או .env למאגר ציבורי. דוגמה ללולאה מקומית שקוראת רק קבצים שמופיעים ברישום:

import csv
from pathlib import Path

ROOT = Path("data/approved").resolve()
with open("manifest.csv", encoding="utf-8", newline="") as f:
    entries = list(csv.DictReader(f))

for e in entries:
    path = Path(e["path"]).resolve()
    if not path.is_relative_to(ROOT) or path.suffix != ".txt":
        raise ValueError("מקור מחוץ לתיקייה המותרת")
    text = path.read_text(encoding="utf-8")
    print(e["source_id"], len(text))  # לא מדפיסים את תוכן המסמך

שלב 3: מכינים חיפוש עם מקור

בשלב ראשון אפשר להשתמש בחיפוש מילים פשוט מתוך מדריך RAG (עם נתוני דוגמה בלבד). כל מקטע צריך source_id, גרסה/תאריך, בעלים ו-allowed_group. כשהשאלה מגיעה:

  1. אמתו את זהות השואל ואת הקבוצות שלו במערכת ההזדהות שלכם.
  2. סננו תחילה מקורות לפי הקבוצות. לא מחפשים במאגר הכללי ואז מבקשים מ-Claude להסתיר תוצאות אסורות.
  3. מצאו עד חמישה מקטעים רלוונטיים, עם מזהי מקור, והעבירו רק אותם ל-Claude API. הוא עונה בעברית עם מקור, או "לא נמצא מידע מורשה".
  4. בדקו בשרת שהציטוט מצביע למקטע שנשלף ושקישור המקור נוצר רק מה-manifest המהימן. תשובת המודל אינה מקור סמכות.

למסמכים רבים אפשר לעבור לאינדקס וקטורי כמו Chroma, אבל embeddings עשויים לשלוח תוכן לספק אחר: Anthropic מתעדת שאין לה מודל embedding משלה. אל תדלגו על סקירת פרטיות וספקים. אם רוצים "Company Brain" שרץ on-prem, בחרו רכיבי אחסון ו-embedding מאושרים מקומית ובדקו האם מותר לשלוח מקטעים ל-Claude API; אם לא, Claude החיצוני אינו מסלול מאושר להפעלה.

שלב 4: איך עובדים עם Claude Code

פתחו את התיקייה המקומית בטרמינל והפעילו claude לאחר התקנה והתחברות לפי ה-Quickstart. תנו לו תחום עבודה וקו עצירה ברורים:

"עבוד רק על app.py וקובצי דוגמה פיקטיביים. קרא את manifest.csv ו-data/approved בלבד. בנה חיפוש עם סינון allowed_group לפני retrieval. אל תתחבר לרשת או למערכות ארגוניות, אל תציג תוכן במסוף, אל תשמור סודות ב-Git. כתוב בדיקות לשאלה מורשית, לשאלה ללא תשובה ולמשתמש ללא הרשאה. הראה diff ועצור לפני כל פעולה שמשנה חיבור או שולחת מידע."

זו הוראה לפיתוח מבוקר, לא בקרת גישה בפועל. הגדירו הרשאות כלי ומערכת קבצים מחוץ לפרומפט; כל הרשאה אמיתית נאכפת בשרת שלכם ובמערכת המקור. Claude Code יכול גם להתחבר ל-MCP; השתמשו ב-claude mcp list כדי לראות חיבורים וב-/permissions לסקור אותם. בלי הרשאה או connector ייעודי הוא לא רואה את SharePoint, SQL או מערכות הקריאות שלכם.

שלב 5: בדיקות לפני הרחבה

  • הריצו את 15 שאלות הבדיקה, חשבו כמה תשובות נשענות על מקור נכון וכמה פעמים הוא אומר "לא יודע" במקום להמציא.
  • בדקו את אותה שאלה כמשתמש מורשה וכמשתמש לא מורשה. לא מספיק שהתשובה חסומה: גם רשימת תוצאות, קישורים ו-snippets חייבים להיות חסומים.
  • בדקו מחיקת מסמך: רענון יומי/שבועי אינו מספיק אם תוכן נמחק או ההרשאה נשללת. נדרש מחיקה מהאינדקס ומזיכרונות ביניים בזמן שמוגדר במדיניות.
  • רשמו source_id, גרסת מסמך, זמן אינדוקס, מזהה השואל ותוצאת בדיקת הרשאות בלי להעתיק תוכן רגיש ללוגים.
  • רק אחר כך עברו למקור הבא. הרחיבו בהדרגה לפי בעל מידע, פרויקט והרשאה ולא לפי "כל הדאטה של החברה".

שאלות שכדאי לשאול את בעל המידע

מי הבעלים? איזו תיקייה/טבלה/פרויקט מותר? למי מותר לראות? מה רמת הסיווג? מתי הנתונים מתעדכנים? מה קורה במחיקה? האם מותר לשלוח טקסט ל-Anthropic או לספק embedding חיצוני? מה מגבלת העלות? תשובות אלה קובעות את התכנון; פרומפט מוצלח אינו מחליף אותן.

מקורות וגבולות

  • Claude Code: MCP, הרשאות, Quickstart: החיבורים, הרשאות כלי והגדרת סביבת עבודה.
  • Anthropic: Embeddings, Tool use, Files API: מה Claude API עושה, איפה הקבצים נשמרים ומגבלות הגישה.
  • Chroma Getting Started: מסד מקטעים וחיפוש.

הדוגמה היא תכנון לימודי. אין כאן חיבור חי למערכות של המשתמש, הרצת קוד עם מפתחות, בדיקת RLS, או הרשאה להעביר דאטה ארגוני לספק חיצוני. גם הקוד וגם תשתית האבטחה דורשים בדיקת סביבה ארגונית לפני שימוש אמיתי.
